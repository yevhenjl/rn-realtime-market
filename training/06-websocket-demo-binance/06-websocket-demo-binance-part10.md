## Уточняющие вопросы: короткие ответы

1. **Почему котировки не в React state и не в TanStack Query?** State — ре-рендер на каждое обновление. Query на каждый `setQueryData` делает structural sharing и будит наблюдателей. Котировки — частый поток, им нужен стор вне React и узкие подписки. Свечу раз в 2 с пишу в кэш Query — это редкое событие.
2. **Как ты доказал, что строки не перерисовываются?** `<Profiler>` вокруг каждой строки и списка, замер 10 секунд: [0] рендеров строк в секунду. Строка рендерится только при монтировании и при смене символа в FlashList.
3. **Почему свой график, а не готовый?** victory-native — хороший вариант: свечи, pan / zoom, press state на Skia; 43.0.1 совместим с моей `react-native-skia` 2.15. TradingView в WebView — богатые функции, но мост `postMessage` на каждое обновление и атрибуция по лицензии. Мне нужен был контроль над live-свечой, rollover и жестами — и понимание механики. В продуктовой команде выбор зависит от требований к индикаторам и сроков.
4. **Rollover и пропуски свечей?** `upsertCandle`: та же `t` — замена, `t + интервал` — новая свеча, дальше — `gap` и перезапрос истории; опоздавшее событие — та же ссылка. После переподключения тоже перезапрашиваю историю.
5. **А 50 000 свечей?** Рисую только видимые (`visibleRange`). Когда на пиксель приходится больше одной свечи — агрегация в старший таймфрейм (`aggregate`). Данные на UI-поток — при изменении, не в кадре.
6. **Как pan и pinch работают без ре-рендеров?** Хуки Gesture Handler 3, колбэки — worklets на UI-потоке, меняют shared values `candleW` и `offset`. Геометрия — derived values. Pan и pinch — simultaneous, перекрестие с ними — competing: кто первым активировался.
7. **Новая свеча во время жеста?** Копия массива на UI-поток раз в 2 с, следующий кадр пересчитает геометрию. Если ты в истории — `followLiveEdge` сдвигает `offset`, картинка не прыгает.
8. **Как замечаешь мёртвый сокет?** Ping / pong видит только нативный слой. Свой heartbeat: 10 с тишины — `LIST_SUBSCRIPTIONS` как ping, 15 с — `close(4000)` и reconnect.
9. **Что в фоне?** На `background` закрываю сокет: iOS всё равно приостановит приложение, Android в Doze режет сеть. При возврате — новое соединение, Query перезапрашивает снимки. Важное в фоне — push.
10. **Backpressure?** Растёт p95 задержки → реже flush, отписка от невидимого, серверный conflation (`@miniTicker` вместо `@trade`).
11. **Как меряешь задержку, если часы телефона врут?** Поправка по `GET /api/v3/time`, как в NTP; задержка = получено + поправка − `E` биржи; смотрю p50 и p95.
12. **Почему flush 200 мс?** Компромисс: плюс до 200 мс задержки против не больше 5 обновлений стора в секунду. Глазу хватает; на мощных устройствах можно 100 мс.
13. **Как гарантируешь корректность стакана?** Алгоритм Binance: буфер, снимок, отбросить `u ≤ lastUpdateId`, проверка `U = id + 1`; дыра — новый снимок. Проверял вживую: 70 секунд без дыр, id совпал с REST.
14. **500 символов и несколько бирж?** Подписка по видимости с `minimumViewTime`; BFF-агрегатор: одна схема, conflation и номера последовательности на сервере; лимиты IP — проблема сервера, а не телефона.
15. **Приватные потоки (ордера)?** Токен первым сообщением, обновление токена при reconnect; conflation нельзя — важно каждое событие и порядок; идемпотентность ордеров.
16. **Почему `react-native-skia` 2.15, а не 2.14 или 3?** 2.14 — последняя версия под старым именем `@shopify/react-native-skia`, её ставит SDK 58, но исправлений больше не будет. 2.15 — тот же нативный Skia и тот же API, пакет живой. 3.x (Graphite) требует Android 8+ (API 26) и Vulkan 1.1 — без Vulkan Canvas пустой; за 19 дней вышло 25 релизов. Мой код без правок проходит `tsc` с типами 3.7.2, размер беру через `onLayout`, а не `onSize`, — переход описан в ADR.
17. **Можно ли показывать данные Binance в open source?** Проект некоммерческий, без логотипов, каждое устройство подключается напрямую, дисклеймер «not affiliated». Для коммерческого использования нужно согласие провайдера.
18. **Как ты использовал AI?** Ядро писал сам по тестам; AI — подсказки по лестнице, ревью в чистом контексте (Claude и Codex), черновики конфигов и README. В каждом PR записано, что сделал AI и что проверил я.
19. **Почему development build, а не Expo Go?** Expo Go — песочница только со своими нативными модулями, для SDK 58 его ещё нет в сторах. Dev build — мой `appId`, мои нативные модули (например, `react-native-skia` 2.15), config plugins и тот же натив, что в релизе; FPS меряю в release-сборке `preview`. `ios/` и `android/` генерирует prebuild (CNG), нативная настройка — в `app.json`. Собираю в EAS: мой Mac для локальной сборки слабый.
20. **Почему Uniwind?** Tailwind CSS 4 через `className`, тема — CSS-переменные, без Babel-пресета. NativeWind 4 — ещё Tailwind 3, а v5 — RC. Unistyles 3 перерисовок не делает, но там нет `className`. Минусы бесплатного Uniwind: `className` не анимируется — анимации у меня в Reanimated; при смене темы перерисовываются компоненты с темой; сторонние компоненты — через `withUniwind`.
21. **Как токены темы попадают в Skia?** Цвета — CSS-переменные в `global.css` (`@variant dark` и `light`). `useCSSVariable` отдаёт строки текущей темы: `color` у `<Path>`, `Paint` в `useMemo` по цвету, `interpolateColor` в worklet. Компонент перерисуется при смене темы, а не на тиках.
22. **`className` вызывает ре-рендеры?** Сам по себе нет: при рендере это поиск по кэшу, а рендеров на тиках у меня нет. Лишний рендер бывает, когда меняется то, от чего зависят классы, например тема. Плохо — переключать `className` на каждом тике: это рендер на тик. Поэтому статика — в `className`, а всё, что меняется на тиках, — shared values и `useAnimatedStyle`.

## Рассказ на 2 минуты

> Это мой open-source демо-проект на React Native — живые котировки и свечной график из публичного WebSocket Binance. WebSocket в продакшене я не делал, поэтому спроектировал и построил проект, чтобы закрыть этот пробел.
>
> Сначала — design doc: требования с числами, лимиты Binance, оценки нагрузки, таблица сбоев и четыре ADR. Потом код. Одно соединение на всё приложение — RealtimeClient вне React: счётчик ссылок, сверка подписок в пределах лимита пять сообщений в секунду, backoff с jitter и свой heartbeat, потому что ping и pong JavaScript не видит. В фоне сокет закрываю, без сети не переподключаюсь, пользователь видит баннер.
>
> Производительность: сообщения проходят Zod, потом conflation — в стор одно обновление раз в 200 миллисекунд. Строки списка подписаны на стор вне React и пишут shared values, поэтому на тиках строки не перерисовываются — мой замер: [0] рендеров. Свечной график — на Skia: четыре пути строятся на UI-потоке, pan, pinch-zoom и перекрестие — жесты Gesture Handler 3, без ре-рендеров; [N] FPS в release. Геометрия — чистые функции с тестами.
>
> Тесты: [N] штук, клиент — с фейковым сокетом и fake timers; я специально ломал код — каждую поломку ловил тест. CI на GitHub, README, лицензия MIT. AI использовал как ревьюера, ядро писал сам. В продакшене добавил бы BFF-агрегатор, подписку по видимым строкам и метрики задержки.

Если перейдут на английский (≈ 1 минута, простыми фразами):

> This is my open-source React Native demo with live prices and a candlestick chart from the public Binance WebSocket. I have not used WebSockets in production, so I designed and built this project to close the gap. I started with a design doc: requirements with numbers, Binance limits, load estimates, failure modes and four decision records. There is one connection for the whole app. It counts subscribers, reconnects with backoff and jitter, and has its own heartbeat. Messages are validated, conflated and written to the store five times per second. List rows read the store outside React, so they do not re-render on ticks. The chart uses Skia: paths are built on the UI thread, and pan, pinch-zoom and the crosshair do not re-render the component. The chart math is pure and tested. I used AI tools for reviews; I wrote the core myself.

Фразы на английском:

- I wrote the design doc before the code; the provider limits are part of the design.
- One connection for the app; screens only subscribe to streams.
- JavaScript cannot see ping frames, so the client has its own heartbeat.
- Rows read the store outside React and update shared values, so they do not re-render on ticks.
- The chart geometry is computed on the UI thread; gestures do not trigger React renders.
- A gap in candles or in the order book means a new snapshot, not a guess.
- The app runs in a development build. Styles use theme tokens, and Skia reads the same tokens.
