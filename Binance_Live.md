# Binance Live — требования к портфолио-проекту на React Native

Черновик · Nov 2, 2026 · @Yevhen

## Контекст и словарь

Приложение показывает публичные рыночные данные Binance Spot в реальном времени. Его задача — доказать навыки работы с WebSocket, Reanimated и Skia. API-ключи, аккаунт и торговля не используются.

**Стек.** React Native (New Architecture) + TypeScript, Expo с dev- и release-сборками, Reanimated 4, Gesture Handler 3, react-native-skia 3.7.4 (Graphite), Zustand, TanStack Query, Zod. Пакеты и версии зафиксированы, менеджер — bun.

**Источники данных.**

- WebSocket: `wss://data-stream.binance.vision` — эндпоинт только для рыночных данных; одно соединение, combined-стримы.
- REST: `https://data-api.binance.vision/api/v3`:
  - `ticker/24hr?type=MINI` — снимок цен для холодного старта списка;
  - `klines` 1m × 500 — история свечей для графика и досинхронизация после разрыва;
  - `klines` 1h × 24 — sparkline в строке списка.

**Ограничения Binance, которые определяют дизайн WS-слоя**

| Ограничение | Значение | Что из этого следует |
| --- | --- | --- |
| Срок жизни соединения | 24 ч | Плановый разрыв — штатный сценарий, не ошибка |
| Ping от сервера | раз в 20 с; без pong в течение минуты — отключение | Pong отправляет сетевой стек сам, без участия JS: OkHttp на Android, SocketRocket на iOS. Из JS ping не виден, поэтому живость соединения проверяет прикладной heartbeat (F4) |
| Сообщения от клиента | не больше 5 в секунду (ping, pong, SUBSCRIBE и т. п.) | Подписки отправляем пакетом: один SUBSCRIBE с массивом стримов |
| Стримов на соединение | до 1024 | Одного соединения хватает на всё приложение |
| Новые соединения | 300 попыток за 5 минут с одного IP | Переподключение только с экспоненциальной задержкой и full jitter; счётчик попыток сбрасывается лишь после 10 с стабильного соединения (NFR-4) |
| Событие serverShutdown | приходит перед остановкой сервера | Переподключаемся сразу, не дожидаясь закрытия сокета, без задержки backoff |
| REST: вес запросов | 6000 weight в минуту на IP; 429 + `Retry-After`; повторы после 429 → 418 (бан от 2 минут до 3 дней) | Запросы 4xx не повторяем, кроме 429 с ожиданием `Retry-After`; кнопка «Повторить» тоже подчиняется этому правилу |
| Регион | HTTP 451 в части стран и облаков | Хосты `*.binance.vision`; 451 — отдельное сообщение «Недоступно в вашем регионе», без автоповторов; тесты и CI без сети |

**Словарь.** Одно значение на слово; спорные слова разобраны в разделе «Проверка на двусмысленность».

- **Символ** — торговая пара Binance, например BTCUSDT.
- **Тик** — сообщение из WebSocket, которое меняет данные символа (miniTicker или kline).
- **Живая цена** — цена последней сделки, поле `c` в miniTicker.
- **Свеча** — OHLC за интервал. Текущая свеча ещё обновляется, закрытая — нет.
- **Ре-рендер** — вызов функции компонента React (фаза render).
- **Release-сборка** — сборка без dev-режима JS и dev-меню. Все замеры производительности — только в ней. Исключение — NFR-2: число рендеров не зависит от типа сборки, а Profiler нужен dev.
- **Возраст данных** — время с получения последнего тика символа, по монотонным часам устройства, пока приложение на экране. В фоне часы не считаем: при возврате возраст неизвестен до первого тика (раздел «Свежесть данных»).

## Цель и функциональные требования F1–F4

**Пользователь видит, как цены 20 выбранных пар Binance меняются в реальном времени, открывает свечной график любой из них, листает, масштабирует и изучает его пальцами — и всегда знает, насколько свежи данные на экране.**

Каждая часть фразы даёт одно требование:

| ID | Часть фразы | Требование | Что демонстрирует |
| --- | --- | --- | --- |
| F1 | «видит, как цены меняются в реальном времени» | Список из 20 фиксированных пар: цена, изменение за 24 ч, sparkline за 24 ч, вспышка на изменение цены | WebSocket, Reanimated (обновление без React), Skia |
| F2 | «открывает свечной график любой из них» | Экран символа: 500 минутных свечей, текущая свеча в реальном времени, объём, шкала цен, линия последней цены | REST + WebSocket, Skia |
| F3 | «листает, масштабирует и изучает его пальцами» | Pan с инерцией, pinch-zoom вокруг пальцев, удержание — перекрестие с OHLC | Gesture Handler 3, Reanimated, Skia |
| F4 | «всегда знает, насколько свежи данные» | Статус соединения: подключаемся, переподключение (попытка N), нет интернета, данные устарели; автопереподключение | Устойчивый WebSocket-слой |
| F5 ★ | — | Стакан и график глубины; лента сделок; мини-игра «прогноз цены» (раздел ★) | WebSocket-слой под нагрузкой, состояние |

F отвечает на вопрос «что пользователь может сделать», NFR — «насколько хорошо». Поэтому F1 выполнено, даже если строки ре-рендерятся на тиках: это нарушение NFR-2, а не F1.

## Три вещи, которые защищаю на интервью

Если урезать всё, остаются три вещи. Каждая закрывает одну технологию из цели проекта, и каждую можно показать на телефоне за минуту.

1. **WebSocket-слой, который переживает мобильную сеть.** Одно соединение на приложение. Подписки (SUBSCRIBE/UNSUBSCRIBE) следуют за открытыми экранами. Переподключение с экспоненциальной задержкой и случайным разбросом, прикладной heartbeat вместо доверия к TCP, досинхронизация свечей через REST после разрыва. Плановый разрыв через 24 ч пользователь не замечает.
   - Готов к вопросам: что будет при переходе с Wi-Fi на LTE; как понять, что сокет мёртв, если close не пришёл; как не потерять свечи за время разрыва.
   - Демонстрация: авиарежим на 15 с — индикатор проходит «Нет интернета → Переподключение → Синхронизация → Live», на графике нет дыры.
2. **Тики не проходят через React-рендер.** Обработчик WebSocket пишет цену в хранилище вне React, на экран она попадает через shared value Reanimated. На тиках 0 ре-рендеров строк (NFR-2), это проверяет тест в CI.
   - Готов к вопросам: почему не useState и не Redux на каждый тик; чем UI-поток отличается от JS-потока; что меняет New Architecture.
   - Демонстрация: React DevTools Profiler, запись 30 с с живыми ценами — ни одного коммита строк.
3. **Свечной график на Skia с жестами на UI-потоке.** Pan с инерцией и pinch-zoom считаются в worklet'ах, Skia рисует без участия JS-потока.
   - Готов к вопросам: почему Skia, а не SVG или View на каждую свечу; как рисовать 1000 свечей без потери кадров; как устроен zoom вокруг точки между пальцами.
   - Демонстрация: кнопка «Заблокировать JS на 3 с» в debug-меню — график продолжает листаться и масштабироваться.

Всё остальное (все ★ из F5, смена интервала, поиск) вырезается без потери истории для интервью. Перекрестие и объём — часть F3 и F2, но на «три вещи» не влияют: при нехватке времени они уходят первыми.

WS-клиент пишет тик в shared value, а строка и график читают его на UI-потоке. React в этом пути не участвует, поэтому на тиках 0 ре-рендеров, а жесты работают даже при занятом JS-потоке.

## F1 — живая цена

Живая цена — цена последней сделки из стрима `<symbol>@miniTicker`. Биржа обновляет этот стрим раз в 1000 мс, и приложение не обещает обновлений чаще.

**Источник**

- 20 стримов `<symbol>@miniTicker` в одном combined-соединении. Один REST-снимок `ticker/24hr?type=MINI` при холодном старте засевает стор; стор сливает данные по времени биржи `E`, поэтому старый снимок не перетирает свежий тик.
- Sparkline: REST `klines` 1h × 24 на символ (weight 2 на запрос) плюс живая последняя точка из тика, не чаще одной пачки conflation (NFR-10).
- Поле `c` — цена последней сделки, `o` — цена открытия скользящего 24-часового окна (не календарных суток UTC).
- Готового процента в miniTicker нет, считаем сами: (c − o) / o × 100.

**Пары (20).** Первые 10, выбраны вручную: BTCUSDT, ETHUSDT, ZECUSDT, NEARUSDT, TAOUSDT, UNIUSDT, SOLUSDT, HYPEUSDT, BNBUSDT, LINKUSDT.

Вторые 10 выбраны по правилу: следующие по 24-часовому объёму пары USDT, без стейблкоинов, токенизированных акций и ETF, золота и символов не из ASCII. Проверено 2026-11-02 по `ticker/24hr` на `data-api.binance.vision`: XRPUSDT, PEPEUSDT, TRXUSDT, SUIUSDT, ENAUSDT, AAVEUSDT, DOGEUSDT, AVAXUSDT, XPLUSDT, WLDUSDT. TRUMPUSDT по правилу проходил, но пропущен: политически окрашенный тикер вызывает вопрос не про realtime.

Ранжирование по объёму — снимок одних суток, поэтому список зафиксирован в коде с датой проверки. Все пары получают 0,4–2,7 сделки в секунду в среднем за сутки (TAOUSDT — самая тихая, 0,42). У PEPEUSDT цена порядка 0,000005: фиксированное число знаков для пары должно давать 8 знаков.

HYPEUSDT — самая новая из пар: на споте Binance она торгуется с 24 сентября 2026 года.

**Что видит пользователь при обновлении**

1. Новое значение цены с фиксированным для пары числом знаков после запятой.
2. Вспышку: цена становится зелёной, если она выше предыдущей полученной, или красной, если ниже, и за 400 мс возвращается к обычному цвету. Цена не изменилась — вспышки нет.
3. Стрелку ▲ или ▼ рядом с ценой, чтобы направление читалось не только цветом.
4. Процент за 24 ч: со знаком «+» зелёный, со знаком «−» красный, ноль — нейтральный.
5. Sparkline за 24 ч: 24 часовые свечи, последняя точка двигается вместе с ценой.

**Минимум, при котором F1 выполнено**

- [ ] Экран показывает 20 пар из списка в коде: символ, живая цена, процент за 24 ч, sparkline.
- [ ] Цена и процент меняются без действий пользователя. После единственного REST-снимка при старте источник — только WebSocket, REST-поллинга цен в коде нет.
- [ ] Рост даёт зелёную вспышку, падение — красную, та же цена — никакой. Функция направления покрыта unit-тестом.
- [ ] Значение в строке равно полю `c` последнего полученного сообщения этой пары. Проверка — debug-оверлей, 5 сверок по разным парам.
- [ ] За 60 с наблюдения строка BTCUSDT обновилась не меньше 30 раз (счётчик тиков в debug-оверлее).

Не входит в минимум: точность цены по `tickSize` из exchangeInfo, сортировка, избранное.

## F2 и F4 — экран символа, пока данных нет

«Данные ещё не пришли» относится к F2: это поведение конкретного экрана при первой загрузке. «Соединение пропало» и «данные устарели» относятся к F4: состояние транспорта общее для обоих экранов, а F1 и F2 только показывают индикатор F4 и не определяют его заново.

Источники экрана: история — REST `GET /api/v3/klines` (1m × 500), живая часть — стрим `<symbol>@kline_1m` с обновлением раз в 2000 мс. На графике: свечи, объём под ними, шкала цен, линия последней цены.

| Состояние | Когда | Что видит пользователь | Требование |
| --- | --- | --- | --- |
| Загрузка истории | Экран открыт, REST ещё не ответил | Заголовок с символом и цена из списка, если она уже есть. На месте графика — скелетон из серых столбиков, спиннера на весь экран нет | F2 |
| Ошибка истории | REST вернул ошибку или не ответил за 10 с | «Не удалось загрузить график» и кнопка «Повторить». Цена в заголовке продолжает обновляться | F2 |
| Ждём стрим | История есть, первого kline-сообщения ещё нет | График из REST, последняя свеча стоит. Индикатор F4: «Подключение…» | F2 + F4 |
| Live | Приходят kline-сообщения | Последняя свеча меняет высоту и цвет. Когда свеча закрывается (`x: true`), справа появляется новая | F2 |
| Нет интернета | NetInfo сообщает, что сети нет | График и цена остаются, вспышки выключены. Индикатор: «Нет интернета». Попыток подключения нет, пока сеть не вернётся | F4 |
| Переподключение | Сеть есть, но сокет закрыт или heartbeat остался без ответа | График и цена остаются, вспышки выключены. Индикатор: «Переподключение (попытка N) · через X с» | F4 |
| Данные устарели | Сокет открыт, но тиков нет ≥ 30 с | Цена и последняя свеча приглушены (прозрачность 50 %). Индикатор: «Обновлено 45 с назад» | F4 |
| Восстановление | Соединение вернулось | Пропущенные свечи догружаются через REST, индикатор «Синхронизация…», затем Live | F4 |

Правило: при потере соединения экран ничего не очищает. Пустой график хуже старого графика с честной пометкой.

**Приоритет состояний F4.** Индикатор показывает одно состояние: первое подходящее сверху.

1. Нет интернета — транспортное состояние: NetInfo.
2. Переподключение (попытка N) — транспортное: сокет закрыт или heartbeat без ответа.
3. Подключение / Синхронизация — сокет открывается или догружаются свечи.
4. Данные устарели — сокет открыт, возраст ≥ 30 с.
5. Задержка — возраст 5–30 с (подпись у цены, не индикатор).
6. Live.

Транспортное состояние всегда важнее возраста. Возраст («Обновлено 45 с назад») показывается внутри индикатора как дополнение, но уровень «Устарело» из одного возраста не выводится, пока сокет закрыт.

## F3 — pan с инерцией и pinch-zoom

Жест выполнен, если соблюдены геометрические критерии ниже и они не ломаются при заблокированном JS-потоке. Слова «плавно» и «быстро» заменены числами в NFR-1.

**Pan**

| ID | Критерий | Как проверить |
| --- | --- | --- |
| P1 | Пока палец на экране, график сдвигается ровно на смещение пальца, ±1 px | Unit-тест функции смещения; запись экрана с сеткой |
| P2 | После отпускания график продолжает движение со скоростью пальца и замедляется до остановки (`withDecay`, коэффициент замедления 0.998 по умолчанию) | Лог смещения: после отпускания оно меняется монотонно и останавливается |
| P3 | Инерция не выводит за границы: справа — последняя свеча плюс отступ в 5 свечей, слева — первая загруженная (`clamp` у `withDecay`) | Сильный бросок в обе стороны — остановка ровно на границе |
| P4 | Если последняя свеча видна, новая свеча сдвигает вид. Если пользователь ушёл в историю, тики вид не двигают | Уйти в историю, дождаться закрытия свечи — вид на месте |
| P5 | Касание во время инерции сразу её останавливает | Бросок, затем касание — движение прекращается |
| P6 | При включённой настройке «Уменьшить движение» pan, инерция и pinch работают так же: у withDecay стоит reduceMotion: ReduceMotion.Never. Анимации, которые запускает не палец, следуют системе: вспышка цены выключается, направление остаётся видно по стрелке | Включить настройку на iPhone и на Galaxy M23 5G, повторить P1–P5 |

**Pinch-zoom**

| ID | Критерий | Как проверить |
| --- | --- | --- |
| Z1 | Точка графика под центром пальцев в начале жеста остаётся под ним до конца: её x-координата не меняется больше чем на ±1 px. Критерий действует внутри пределов Z2 и границ P3: на пределе масштаба или у края истории точка остаться на месте не может | Unit-тест чистой функции масштаба вокруг фокальной точки на случайных viewport, фокусах и масштабах |
| Z2 | Видно от 20 до 200 свечей; на пределе масштаб дальше не меняется | Свести и развести пальцы до упора, посчитать свечи |
| Z3 | Pan и pinch работают одновременно: двумя пальцами можно и сдвигать, и масштабировать | Ручная проверка |

**Перекрестие (удержание)**

| ID | Критерий | Как проверить |
| --- | --- | --- |
| C1 | Удержание пальца дольше порога (стартово 300 мс) показывает вертикальную линию и подпись: время, OHLC и объём свечи под пальцем | Unit-тест функции «x → индекс свечи»; ручная проверка |
| C2 | Пока перекрестие активно, палец не сдвигает график; перекрестие следует за пальцем и привязано к свече | Ручная проверка |
| C3 | Отпускание скрывает перекрестие; удержание не ломает pan и pinch (P1–P5, Z1–Z3). Конфликты жестов решает композиция Gesture Handler 3 | Ручная проверка |

**Главная проверка — заблокированный JS-поток.** В debug-меню есть кнопка, которая занимает JS-поток циклом на 3 с. Во время блокировки P1–P3, P5, Z1–Z3 и C1–C3 продолжают выполняться: значит, жесты и отрисовка от JS-потока не зависят. Тики в это время не обновляются, это ожидаемо.

**Почему инерция не отключается при «Уменьшить движение».** WCAG 2.3.3 считает прокрутку, которую пользователь запускает и контролирует сам, необходимым движением; отключать нужно только необязательную анимацию. В Reanimated по умолчанию стоит `ReduceMotion.System`, и при включённой настройке `withDecay` сразу возвращает текущее значение — инерция просто пропала бы.

Числа 5, 20 и 200 стартовые, уточнить после прототипа. Математика viewport живёт в чистых worklet-функциях, чтобы тестировать её в Jest без устройства.

## Нефункциональные требования

Каждое NFR — это число, условия и инструмент замера. Все замеры производительности делаются в release-сборке на реальном устройстве; цифры из dev-сборки и эмулятора не считаются.

**Устройства для замеров.** Основное — Samsung Galaxy M23 5G, Android 14: по нему принимаются NFR-1, NFR-3, NFR-7 и NFR-9. Дополнительное — iPhone, модель уточнить.

Экран M23 5G работает на 120 Гц: на кадр есть 8,3 мс, а не 16,7 мс. Режим плавности экрана фиксируем до замера и пишем в отчёт, потому что цифры при 60 и 120 Гц несравнимы.

**Общие условия:** локальная release-сборка (`bun run android --variant release`, на iOS — `bun run ios --configuration Release`; облачная сборка EAS — только по явному запросу), подписка на 20 miniTicker и 1 kline, Wi-Fi, режим энергосбережения выключен.

## NFR-2 — «0 ре-рендеров строк на тиках»

Ре-рендер — вызов функции компонента строки (`WatchlistRow` и всего внутри неё) React'ом. Требование: после монтирования строка не рендерится ни от тиков, ни от таймеров, ни по любой другой причине, кроме перечисленных ниже.

**Считается ре-рендером:** любой вызов функции `WatchlistRow` или её дочерних компонентов, кроме перечисленных ниже. Причина не важна: тик, таймер метки возраста, смена состояния.

**Не считается:**

- обновление нативного свойства через Reanimated (`useAnimatedProps`, `useAnimatedStyle`) — React в нём не участвует;
- рендер при монтировании, прокрутке (переиспользование ячеек списка), смене состава списка или темы;
- двойной рендер при монтировании в StrictMode.

**Как цена попадает на экран без рендера**

- Путь тика: WebSocket-клиент → Zod → conflator (последнее значение по символу) → flush раз в 200 мс → Zustand-стор котировок (≤ 5 обновлений в секунду, NFR-10).
- Строка подписана на стор транзиентно, без React: подписка пишет `.set()` в shared value на символ (цена и направление последнего изменения). Читаем через `.get()`: при включённом React Compiler `.value` не используется.
- Строка рисует цену компонентом `Text` из Skia: строка текста и цвет — derived value от этого shared value.
- Решение: текст в Skia, а не анимируемый `TextInput`. Следствия: шрифт загружается до показа списка; нужен шрифт с цифрами одинаковой ширины, чтобы число не «прыгало»; скринридер не видит текст на Canvas (см. «Открытые вопросы»).

**Как это видно**

1. **Тест в CI, основной способ.** Jest и React Native Testing Library: рендерим список, считаем рендеры строк через `React.Profiler` (`onRender`) или счётчик в dev-сборке. Затем отправляем 100 синтетических тиков через тот же API хранилища, что и WebSocket-клиент, и прокручиваем fake timers на 60 с (общий таймер метки возраста). Ожидаем 0 рендеров строк после монтирования.
2. **React DevTools Profiler.** Запись 30 с живых тиков без касаний — в ней нет коммитов с `WatchlistRow`, подсветка рендеров на строках не мигает.
3. **Debug-оверлей.** Счётчик рендеров на каждой строке (только dev-сборка) стоит на месте, пока цены меняются.

Тест должен падать, если в строку вернуть `useState` для цены: один раз сломать нарочно и убедиться. Число рендеров не зависит от типа сборки, поэтому NFR-2 меряем в dev-сборке, где доступен Profiler.

## Свежесть данных

**Обещание пользователю: если рядом с ценой нет пометки, данным меньше 5 секунд.** Старше 5 с — показываем возраст, старше 30 с — помечаем данные как устаревшие.

**Как считаем возраст.** Возраст — это текущее время минус момент получения последнего тика по символу. Берём монотонные часы устройства, а не поле `E` биржи: часы телефона могут расходиться с биржевыми на секунды.

**Часы и сон устройства.** Монотонные часы могут останавливаться в глубоком сне: по документации Android `SystemClock.uptimeMillis()` не идёт в deep sleep, а `elapsedRealtime()` идёт. Как себя ведёт `performance.now()` в Hermes на Android и iOS при сне, я не подтвердил, поэтому на это не опираемся. Возраст считаем только пока приложение на экране; уход в фон закрывает сокет и сбрасывает знание о возрасте. При возврате возраст не вычисляем, а объявляем неизвестным до первого тика (см. «Фон и возврат»).

**Как метка возраста обновляется без React-рендера.**

- Один общий таймер на всё приложение, не по таймеру на строку: раз в секунду он пишет текущее время в один shared value.
- Таймер работает только пока приложение на экране и останавливается в фоне (NFR-13).
- Строка выводит из этого значения derived value: возраст = текущее время − время последнего тика. Из него же получаются текст метки «12 с назад», пороги 5 и 30 с, приглушение и выключение вспышки. Всё это живёт на UI-потоке, поэтому рендера нет.
- Время последнего тика пишется при flush (раз в 200 мс). Обе величины меряются одними часами.
- Индикатор F4 на экране — один компонент, он может быть React-состоянием: транспортные состояния меняются редко. Секундная подпись внутри него использует то же derived value.

**Почему 5 и 30 секунд.** miniTicker приходит раз в 1 с, kline — раз в 2 с. Порог 5 с — это от 2 до 5 пропущенных обновлений подряд: случайная задержка сети пометку не вызовет, реальная проблема вызовет. За 30 с текущая минутная свеча проживает половину своей жизни, и показывать её как живую уже нечестно.

**Приходит ли miniTicker, если сделок не было.** Документация прямо не отвечает. Для `!miniTicker@arr` сказано, что в массив попадают только изменившиеся пары; для одиночного `<symbol>@miniTicker` указана только частота 1000 мс, без такой оговорки.

Поэтому проверяем замером: debug-лог интервалов между сообщениями по каждой из 20 пар за 30 мин в тихие часы. Если при живом heartbeat у пары бывают паузы дольше 5 с, порог «Задержка» для неё поднимаем до наблюдаемого максимума.

| Уровень | Возраст | Что видит пользователь | Что делает приложение |
| --- | --- | --- | --- |
| Live | < 5 с | Ничего дополнительного | — |
| Задержка | 5–30 с | Серая подпись «12 с назад» у цены | Ждёт, соединение не трогает |
| Устарело | ≥ 30 с при открытом сокете | Цена и последняя свеча приглушены, вспышки выключены, индикатор «Данные устарели · 45 с» | Сокет открыт, но тиков нет: проверяет подписки и закрывает соединение, если heartbeat без ответа (NFR-9) |

Закрытый сокет и отсутствие сети в эту таблицу не входят: это транспортные состояния F4 с более высоким приоритетом (раздел «F2 и F4»).

**Heartbeat — два уровня.**

- Протокольный: сервер шлёт ping раз в 20 с, pong отвечает сетевой стек. Из JS этот уровень не виден.
- Прикладной, наш: после 5 с без сообщений клиент отправляет `LIST_SUBSCRIPTIONS` с `id` и ждёт ответ 5 с. Нет ответа — соединение полуоткрытое: закрываем и подключаемся заново. Ответ пришёл — соединение живо, просто рынок молчит; время ответа заодно даёт RTT.

Обрыв обнаруживается не позже чем за 10 с (NFR-9). Heartbeat тратит не больше одного сообщения в 5 с при лимите 5 сообщений в секунду.

**Фон и возврат.** При уходе приложения в фон сокет закрываем и возраст не считаем. При возврате:

- индикатор «Подключение…» (транспортное состояние по приоритету F4), а не «Устарело»: возраст неизвестен, а не ≥ 30 с;
- цена и последняя свеча приглушены, как в «Устарело», пока не придёт первый тик;
- пропущенные свечи догружаются через REST (NFR-5), индикатор «Синхронизация…», затем Live.

**Ограничение.** Пороги рассчитаны на ликвидные пары, поэтому список фиксирован и состоит только из них. Все пороги — константы в одном конфиг-файле.

## Проверка на двусмысленность

В черновике 14 слов, которые другой разработчик может понять двумя способами; каждое закреплено одним значением. Слова «плавно» и «быстро» запрещены и везде заменены числами.

| Слово | Первое прочтение | Второе прочтение | Как закреплено |
| --- | --- | --- | --- |
| Живая цена | Цена последней сделки | Середина между bid и ask или close свечи | Цена последней сделки, поле `c` miniTicker (F1) |
| Тик | Любое сообщение из сокета | Только изменение цены | Сообщение, меняющее данные символа. Ответ на SUBSCRIBE — не тик |
| В реальном времени | На каждую сделку | С частотой источника | С частотой стрима: miniTicker 1000 мс, kline 2000 мс |
| Ре-рендер | Вызов render в React | Перерисовка пикселей | Только вызов функции компонента React (NFR-2) |
| 60 FPS | JS-поток, среднее | UI-поток, минимум | UI-поток: ≤ 5 % медленных кадров на частоте экрана, release-сборка (NFR-1) |
| Соединение пропало | Сокет закрыт | Сокет открыт, но данных нет | Оба случая: событие close или heartbeat без ответа (до 10 с) |
| Устаревшие данные | Старше 5 с | Старше 30 с | 5–30 с — «Задержка», от 30 с при открытом сокете — «Устарело»; закрытый сокет — отдельное транспортное состояние с более высоким приоритетом |
| Загрузка | Первая загрузка истории | Переподключение | Первая загрузка — F2; «Подключение» и «Синхронизация» — F4 |
| Свеча | Закрытая | Текущая | Текущая обновляется, закрытая (`x: true`) — нет |
| Инерция | Движение после отпускания | Сглаживание под пальцем | Только после отпускания; под пальцем — 1:1 (P1, P2) |
| Изменение за 24 ч | Календарные сутки UTC | Скользящее окно | Скользящее 24-часовое окно, как в miniTicker |
| Release-сборка | Expo Go или dev client | Production-сборка | Сборка без dev-режима JS: `--variant release` или конфигурация Release |
| Символ | Пара BTCUSDT | Актив BTC | Торговая пара |
| Heartbeat | Ping/pong протокола WebSocket | Прикладная проверка соединения | Оба уровня названы явно: ping/pong отвечает сетевой стек, прикладной — запрос LIST\_SUBSCRIPTIONS после 5 с тишины (раздел «Свежесть данных») |

Как проверять дальше: дать раздел F1–F4 другому разработчику и попросить пересказать критерии готовности своими словами. Где пересказ разошёлся с текстом — там ещё одна двусмысленность.

## Открытые вопросы

- [x] Устройство: Samsung Galaxy M23 5G, Android 14, экран 120 Гц; iPhone есть.
- [x] Вывод цены — текст в Skia (раздел NFR-2).
- [x] Pong на ping сервера отправляет сетевой стек сам: OkHttp на Android, SocketRocket на iOS (раздел «Контекст и словарь»).
- [x] miniTicker без сделок: документация однозначно не отвечает, меряем сами (раздел «Свежесть данных»).
- [x] «Уменьшить движение»: жесты и инерция работают всегда, остальные анимации следуют системе (F3, P6).
- [x] Первые 10 из 20 пар выбраны (F1).
- [x] Условия использования API Binance прочитаны: для публичного демо подходят.
- [ ] Замерить интервалы miniTicker по 20 парам в тихие часы; первой смотреть TAOUSDT (≈ 0,42 сделки в секунду).
- [ ] Модель iPhone и частота его экрана.
- [ ] Проверить в `Podfile.lock`, что WebSocket на iOS работает через под SocketRocket.
- [ ] Решить, как скринридер узнаёт текущую цену, если она нарисована в Skia, а подпись строки на тиках не обновляется.
- [ ] После прототипа уточнить: отступ справа (5 свечей), пределы масштаба (20–200), числа в NFR-3 и NFR-7.
- [x] Список ★ сверен с курсом: F5 — стакан, лента сделок, «прогноз цены».
- [x] Вторые 10 пар выбраны по правилу объёма (F1).
- [ ] Перерисовать диаграмму по стеку: добавить Zod и conflator (flush 200 мс) между WS-клиентом и хранилищем; свечи и снимки живут в TanStack Query, а не в Zustand; запись в shared value — `.set()`.
- [ ] ADR 0003: курс пишет «графики без требования Vulkan», а `AGENTS.md` фиксирует Skia Graphite с Vulkan 1.1 (Android API 26+, iOS 15.1+). В NFR-14 взят более строгий минимум, расхождение Vulkan решает ADR.
- [ ] Решения по F5 ★: стакан, лента сделок, «прогноз цены».
- [ ] Проверить на устройстве, останавливается ли монотонный `performance.now()` в сне (на ответ не опираемся: возраст считаем только на экране).
